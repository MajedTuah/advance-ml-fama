MODULE 1 · ACTIVITY · about 3 min

Four ways information leaks into training

Leakage gives an optimistic score and a disappointing production model

Target leakage

A feature is created after, or because of, the outcome.

days_to_default, post_approval_status_flag

FIXKeep only what is known at decision time.

Train-test contamination

A transformer is fitted on all rows before the split.

Scaler fitted on the full dataset

FIXSplit first. Fit inside a Pipeline.

Temporal leakage

A random split lets the model learn from the future.

2025 loans used to score 2023

FIXTime-ordered split or TimeSeriesSplit.

Group leakage

The same customer appears on both sides of the split.

A repeat borrower in train and test

FIXGroup by customer_id.

scikit-learn guidance. Split before any preprocessing, and keep every fitted step inside a Pipeline.

The leakage-free pattern

Same data, same model. Only the order of operations changes.

WRONG
Full dataset→Fit imputer and scaler on all rows→Random split→Train→Evaluate

Test-set statistics and future loans shape training. The score is optimistic.

RIGHT
Full dataset→Time-ordered split, oldest 80%→Fit Pipeline on train only→Tune on validation folds→Score the newest 20% once

The holdout looks like next month's applicants, so the score estimates production.

df = df.sort_values("loan_approval_date")
cut = int(len(df) * 0.8)          # oldest 80% trains
train, test = df.iloc[:cut], df.iloc[cut:]

num = ["loan_amount", "annual_income", "employment_years",
       "credit_score", "days_since_last_payment", "existing_loans"]
cat = ["loan_type", "region"]

num_pipe = Pipeline([
    ("impute", SimpleImputer(strategy="median")),
    ("scale", StandardScaler())])
cat_pipe = Pipeline([
    ("impute", SimpleImputer(strategy="most_frequent")),
    ("onehot", OneHotEncoder(handle_unknown="ignore"))])
pre = ColumnTransformer(
    [("num", num_pipe, num), ("cat", cat_pipe, cat)])
model = Pipeline([
    ("pre", pre),
    ("clf", LogisticRegression(max_iter=1000))])
model.fit(train[num + cat], train["defaulted_in_next_30_days"])

fit() learns from train only

Medians, scales and categories never see the test rows.

The same object everywhere

Validation, batch scoring and the API all call one Pipeline.

Parameters versus hyperparameters

What the model learns, versus what you decide before training

Model parameters

Learned from data during fit().

  • Logistic regression coefficients
  • Tree split thresholds
  • Neural network weights

Hyperparameters

Set by you before training starts.

  • n_estimators, max_depth
  • learning_rate, C
  • min_samples_split

Baking analogy

Oven temperature and time are hyperparameters. How the ingredients combine is learned. Set them badly and the cake burns: the model overfits.

Golden rule

Tune on validation folds. Never let the test set choose the hyperparameters.

def objective(trial):
    params = {
        "n_estimators": trial.suggest_int("n_estimators", 50, 300),
        "max_depth": trial.suggest_int("max_depth", 3, 20),
        "min_samples_split": trial.suggest_int("min_samples_split", 2, 15),
    }
    clf = RandomForestClassifier(**params, random_state=42)
    # validation folds, never the test set
    scores = cross_val_score(
        clf, X_train, y_train, cv=3, scoring="roc_auc")
    return scores.mean()

study = optuna.create_study(direction="maximize")
study.optimize(objective, n_trials=20)
print(study.best_params, round(study.best_value, 3))
Trial

One evaluation of one set of hyperparameters.

Study

The whole search: every trial, plus the best.

Sampler

Chooses the next trial. TPE, a Bayesian sampler, is the default.

Pruner

Stops a hopeless trial early and saves compute.

MODULE 3 · 2:05–3:00

Why explainability matters

“Your model denied my loan. Why?”

LAW

GDPR Article 22 and rules like MAS FEAT expect an explanation of an automated decision.

TRUST

An underwriter will not adopt a model they cannot question.

DEBUG

Catch shortcuts. One vision model learned to detect hospital rulers, not tumours.

BIAS

Surface proxies for protected attributes such as age or gender.

AUDIT

Keep a reproducible trail for a decision you made six months ago.

THE TRANSPARENCY SPECTRUM

Linear / logistic. Glass box. Read the weights.

Trees / GAMs. Readable rules, up to a point.

Forest / XGBoost. Needs post-hoc SHAP.

Neural nets / LLMs. Black box. SHAP and LIME.

Modern answer. Train the best model, then explain it. You no longer trade accuracy for a conversation with risk.

MODULE 3 · 2:05–2:25

SHAP: fair credit for every feature

Shapley values from cooperative game theory (Lundberg & Lee, 2017)

The intuition

Features are players. The prediction is the score. SHAP gives each feature its average marginal contribution across every possible line-up.

f(x) = E[f(X)] + Σ φᵢ

  • Additivity: contributions sum to the prediction
  • Consistency: more influence never lowers the value
  • Missingness: a useless feature gets exactly 0
import shap
explainer = shap.TreeExplainer(model)
shap_values = explainer.shap_values(X_test)

# Global: what drives the portfolio?
shap.summary_plot(shap_values, X_test)

# Local: why this one applicant?
shap.waterfall_plot(shap.Explanation(
    values=shap_values[0],
    base_values=explainer.expected_value,
    data=X_test.iloc[0]))

MODULE 3 · OPEN CHANNEL 04 · 5 MIN

Three kinds of drift

The world moves after training. The model does not.

Feature drift

P(X) changes

The inputs shift.

A new digital channel brings much younger applicants.

DETECTPSI and KS on every input. Available immediately.

Concept drift

P(y | X) changes

The rules change.

After a rate rise, the same debt-to-income ratio means more risk.

DETECTPerformance on newly labelled loans. Labels take months.

Label drift

P(y) changes

The outcome rate shifts.

The default rate doubles from 3% to 6% in a downturn.

DETECTPredicted default rate against the realised rate.

Measuring drift: PSI and the KS test

Training month versus one simulated production month. Same numbers as the next activity.

POPULATION STABILITY INDEX

PSI = Σ (Aᵢ − Eᵢ) · ln(Aᵢ / Eᵢ)

Ten bins cut on the training quantiles. E is the training share, A is production.

STABLE
< 0.10
WATCH
0.10 – 0.20
ALERT
≥ 0.20

KOLMOGOROV-SMIRNOV

D is the biggest gap between the two cumulative distributions. With thousands of rows, KS flags tiny shifts. Pair it with PSI before you act.

FastAPI and Pydantic

class PredictRequest(BaseModel):
    age: int = Field(..., ge=18, le=120)
    income: float = Field(..., gt=0)
    credit_score: int = Field(..., ge=300, le=850)

class PredictResponse(BaseModel):
    prediction: str
    probability: float

@app.get("/health")
async def health_check():
    return {"status": "healthy"}

@app.post("/v1/predict", response_model=PredictResponse)
async def predict(req: PredictRequest):
    if req.income > 60000 and req.credit_score > 650:
        return PredictResponse(
            prediction="No Default", probability=0.1)
    return PredictResponse(
        prediction="Default", probability=0.85)
